05
Query Embedding + Cosine Similarity
Q → q ∈ ℝ³⁸⁴  →  cos(θ) = (q·vᵢ)/(‖q‖·‖vᵢ‖) for all i
Similarity ★
▼
cos(θ) =  q · vᵢ ‖q‖ · ‖vᵢ‖ = q · vᵢ (unit vectors)
=  Σj=1384 qj · vij
‖q‖ = √(q₁²+q₂²+⋯+q₃₈₄²)  ∈  [0, 1]
After L2-normalization, cosine similarity reduces to a dot product. Value 1 = identical semantic direction. Value 0 = completely unrelated topics. Real text embeddings stay in [0, 1].
Step-by-step dot product → cosine derivation
①
x = [1, 2, 3]      y = [4, 5, 6]
Example 3D vectors (real embeddings are 384-dim)
②
x·y = 1×4 + 2×5 + 3×6 = 4 + 10 + 18 = 32
Dot product: sum of element-wise products across all dimensions
③
‖x‖ = √(1+4+9) = √14 ≈ 3.742    ‖y‖ = √(16+25+36) = √77 ≈ 8.775
L2 norms = Euclidean lengths of the two vectors
④
cos(θ) = 32 / (3.742 × 8.775) = 32 / 32.84 ≈ 0.974
Very high similarity — vectors point in nearly the same direction
⑤
After L2-normalize: x̂·ŷ = cos(θ) directly — no division needed!
SBERT pre-normalizes all vectors so RAG uses plain dot product

06
Top-K Retrieval & Context Assembly
TopK = argmax_k {s₁,…,sₙ} → assembled context P → LLM generation
Retrieval ★
▼
TopK = { i : sᵢ ≥ s(n−k+1) } = argmaxk{ s1,…,sn }
P = "Context: " ⊕ Cσ(1) ⊕ … ⊕ Cσ(k) ⊕ " Q: " ⊕ Q
Confidence = (1/k) Σi=1k cos(q, vσ(i))
σ is the index-permutation that sorts chunks by descending similarity. ⊕ = string concatenation. Assembled prompt P feeds an LLM constrained to answer only from context.
①
Sort: s₁ ≥ s₂ ≥ … ≥ sₙ (descending cosine scores)
②
Select Top-K: {σ(1), σ(2), σ(3)} (k = 3 default)
③
Threshold: discard if score < 0.25 (too dissimilar)
Prevents noisy low-relevance context from polluting the answer
④
Assemble: Context ← C_σ(1) + C_σ(2) + C_σ(3)
⑤
Prompt P = [SYSTEM_PROMPT] + Context + [QUESTION: Q] → LLM

📐 Complete Mathematical Reference
Chunking
n = ⌈(|D|−o)÷(k−o)⌉
Ci = {w(i-1)(k-o)+1…wi(k-o)+o}
k=500 chunk size, o=50 overlap. Each chunk shares o words with the next — preserving boundary context.
L2 Normalization
‖v‖₂ = √(Σⱼ vⱼ²) = 1
v̂ = v / ‖v‖₂
Projects every vector onto the unit hypersphere. Removes magnitude differences — only semantic direction matters.
Cosine Similarity
cos(θ) = q·v / (‖q‖·‖v‖)
= Σⱼ qⱼ·vⱼ  (unit vectors)
Measures the angle θ between query q and chunk v. Range [−1,1]; text embeddings ≈ [0,1].
Dot Product
x·y = Σᵢ xᵢyᵢ = x₁y₁+…
= ‖x‖·‖y‖·cos(θ)
Algebraic: element-wise sum. Geometric: product of lengths × cosine of angle. These are identical.
Top-K Selection
TopK = argmaxk{s₁…sₙ}
Conf = (1/k)Σᵢ sᵢ
Select k chunks with highest cosine score. Mean similarity = confidence. Low confidence warns of poor retrieval quality.
TF-IDF Boost
tf(t,d) = f(t,d)/|d|
idf(t) = log((N+1)/(df+1))+1
score += tf·idf (capped)
Rare query terms in a chunk get extra weight. Bridges the vocabulary gap where semantic similarity misses surface-level keyword matches.
Embedding Space
E: text → ℝ³⁸⁴
‖E(C)‖₂ = 1 ∀C
SBERT (all-MiniLM-L6-v2) maps any text length to a fixed 384-dim unit vector. Nearby vectors = semantically similar text.
Matrix Retrieval
V ∈ ℝn×384
scores = V · q ∈ ℝⁿ
All n chunk embeddings stacked row-wise. One matrix-vector multiply computes all n cosine scores simultaneously — GPU-parallelizable.
